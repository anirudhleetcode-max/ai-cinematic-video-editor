# Benchmarks (measured)

## Real footage — release measurements

**Machine:** Linux container, Intel Xeon @ 2.80 GHz, **4 CPU cores**, 15.7 GB RAM, **no GPU**, FFmpeg 6.1.1, encoder
libx264 (CPU only; no hardware encoder exists here, none is claimed).
**Input:** `tests/real_media/event01` — 76 real clips (851.6 s of footage; H.264 ×70, VP9, MJPEG, ProRes, HEVC; 13
resolutions from 640×360 to 3840×2160, incl. portrait 1080×1920), 3 songs, 1 reference, 1 logo.
**Output:** 1920×1080, 30 fps, H.264 / AAC, Fast mode. Analysis is one-off per project and listed separately.
Raw data: [`real_benchmarks.json`](real_benchmarks.json) (clean run), [`real_benchmarks_run2.json`](real_benchmarks_run2.json).

### Against the 25-minute target
* **5-minute edit: measured 975 s (16.3 min)** including analysis, preview and final (clean run). Within 25 min.
* **10-minute edit: measured 1977.7 s (33.0 min)** including analysis (148.4 s), preview and final (run 2, not
  isolated). Final render alone 1305.0 s (21.8 min). **Above the 25-minute target on this 4-core CPU-only machine**
  when a preview is rendered first; without the preview it would be analysis + final ≈ 1457 s (24.3 min) — that
  combination was **not** run, so it is an estimate from measured parts, not a measurement.
* Improvement from the first real run (before rendering the grade into segments): 300 s final 956.6 → 649.9 s
  (−32 %); 600 s final 1922.1 → 1305.0 s (−32 %, run 2).

## Synthetic media (earlier engine benchmark)

Every number here was measured by `scripts/benchmark.py` and `scripts/acceptance_test.py` on the machine below;
raw results are in [`benchmarks.json`](benchmarks.json) and [`acceptance_report.json`](acceptance_report.json).
Re-run on your hardware with `npm run benchmark`. Results on other machines will differ.

**Machine:** Linux container, 4 CPU cores, 15.7 GB RAM, **no GPU**, FFmpeg 6.1.1, encoder libx264 (CPU).
**Media:** synthetic DEMO clips (3–8 s each, 1280×720, generated by `editor.testmedia`), including deliberately bad
shots (blurry, dark, overexposed, shaky, black, frozen, duplicates), 3 songs, 1 reference, 1 logo. Clip counts include
one generated duplicate. **Output:** 60 s, 1920×1080, H.264/AAC, Fast mode.

| Clips | Analysis | Planning | Render (incl. QC) | Total | Peak RSS | Avg CPU | Disk used | QC |
|---:|---:|---:|---:|---:|---:|---:|---:|:-:|
| 11 | 8.8 s | 0.04 s | 132.5 s | **141.4 s** | 1.79 GB | 77 % | 0.50 GB | pass |
| 26 | 9.5 s | 0.02 s | 161.3 s | **170.8 s** | 1.95 GB | 76 % | 0.90 GB | pass |
| 51 | 14.6 s | 0.02 s | 157.8 s | **172.5 s** | 2.04 GB | 75 % | 0.99 GB | pass |
| 101 | 25.1 s | 0.03 s | 164.0 s | **189.1 s** | 1.84 GB | 76 % | 1.63 GB | pass |
| 201 | 46.2 s | 0.04 s | 174.6 s | **220.8 s** | 1.77 GB | 78 % | 2.63 GB | pass |

Render breakdown (201 clips): segments 59.2 s · transitions 11.8 s · audio mix 6.5 s · final pass 86.8 s · QC 10.3 s.

Observations:
* Analysis scales roughly linearly with footage; render time depends on **output** length, not on the number of inputs.
* The final pass (concat → grade → text → x264 encode at 1080p) is the largest single stage on CPU; a verified
  hardware encoder would shorten it, but none was available here.
* Synthetic-media generation time (not part of the product pipeline) is excluded from the totals.

## Acceptance run (spec §76)

50 clips + 3 songs + 1 reference, the full spec prompt, Fast mode, 1080p output — **all 14 checks passed**
(total 678 s including synthetic media generation):

| Step | Measured |
|---|---|
| Upload (56 assets) + analyse | 9.7 s + 17.8 s; 16 of 56 shots usable (blurry 14, underexposed 16, frozen 9, duplicates 13, …), **no rejected shot used** |
| Plan | 0.03 s, 61 segments, reference profile applied, logo + title ending |
| Preview render (640 px) | 46.7 s, QC pass |
| Final render 60 s 1080p | 139.9 s, QC pass, −16.0 LUFS, −1.0 dBTP |
| “Make it more energetic and reduce the intro to 3 seconds.” | 147.0 s; 61 → 90 segments, intro exactly 3.0 s, all 61 previous picks kept |
| “Make the colors warmer.” | 76.0 s; timeline unchanged, **90/90 segments reused from cache** |
| “Use song 2 for the final section.” | song 2 was already the auto-selected song, so this is reported as a no-op (0 s, no re-render) |
| “Use song 3 for the final section.” (extra, to exercise a real change) | 138.5 s; final section switched to song 3, earlier sections unchanged, colour kept |
